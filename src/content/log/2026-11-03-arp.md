直连路由只说明「这个网段从本口出去」。真正发出去时，帧上要写下一跳的 MAC。ARP 就是在问：这个 IP 的 MAC 是多少。问的是广播，所以只在同一个 VLAN 里有人回答。另一个 VLAN 里的主机听不到。

```bash
ip netns add h1
ip netns add h2
ip link add v1 type veth peer name v2
ip link set v1 netns h1
ip link set v2 netns h2
ip netns exec h1 ip addr add 192.168.10.1/24 dev v1
ip netns exec h2 ip addr add 192.168.10.2/24 dev v2
ip netns exec h1 ip link set v1 up
ip netns exec h2 ip link set v2 up

ip netns exec h1 ip neigh show
ip netns exec h1 ping -c 1 192.168.10.2
ip netns exec h1 ip neigh show
```

第一次 `ip neigh` 是空的。ping 之后出现 `192.168.10.2`，后面跟着 h2 的 MAC，状态一般是 `REACHABLE`。这一行才是发出去时用的目的 MAC。

把表清掉再 ping，会重新问一次，然后又出现：

```bash
ip netns exec h1 ip neigh flush all
ip netns exec h1 ping -c 1 192.168.10.2
ip netns exec h1 ip neigh show
```

再写成一条错误的永久表项。路由没动，地址也没变，ping 会超时，因为帧被送到一个没有人的 MAC：

```bash
ip netns exec h1 ip neigh replace 192.168.10.2 lladdr 00:11:22:33:44:55 dev v1 nud permanent
ip netns exec h1 ping -c 1 -W 1 192.168.10.2
ip netns exec h1 ip neigh del 192.168.10.2 dev v1
ip netns exec h1 ping -c 1 192.168.10.2
```

删掉错误表项之后，再 ping 会重新学到正确的 MAC。

看状态时记三种就够。空的，是还没问。`FAILED`，是问了没有人答，常见原因是对方不在这个 VLAN，或者口是 down 的。有 MAC 但 ping 不通，先核对这行 MAC 是不是对方接口上的那个，命令是 `ip netns exec h2 ip link show v2`。

```bash
ip netns del h1
ip netns del h2
```
