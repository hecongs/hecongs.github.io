交换机收到一帧，先看源 MAC，把「这个 MAC 从本口进来」写进 MAC 表。之后发给这个 MAC 的帧只从该口出去，不再对所有口洪泛。表里没有的目的 MAC，仍然洪泛。过一段时间没有再学到，表项老化，又变回洪泛。

这是学习，不是配置出来的。测试要看的是学到的端口对不对。把两台主机接在不同口上互 ping，表里两台的 MAC 应分别落在各自的端口。把主机换一个口再 ping，表应改到新口。还停在旧口，流量会打到已经没人的地方。

VLAN 是在这张二层上再切开。同一个 VLAN 里的端口才能互转广播和单播。不同 VLAN 之间，交换机不转发，即使两边 IP 配在同一个网段。Access 口只属于一个 VLAN，线上的帧不带 tag。Trunk 口可以带多个 VLAN，帧上有 tag，用来在交换机之间或接到需要同时进多个 VLAN 的设备。

实验时故意把第三台主机放进另一个 VLAN，IP 仍用同一网段。ping 不通，才说明隔离生效。若仍能通，不是「网段相同所以应该通」，是 VLAN 没切开，或者 Trunk 把两个 VLAN 又桥到了一起。

在 Linux 网桥上可以看两张表：`bridge fdb show` 看 MAC 落在哪个口，`bridge vlan show` 看每个口的 VLAN 和有没有 tag。总览里的网桥命令按这个现象去对。

## 不带 tag 的帧进哪个 VLAN

Access 口收到的帧没有 tag。它被放进这个口的 PVID。总览里的 `v1b` 可以这样标：

```bash
bridge vlan add dev v1b vid 10 pvid untagged
bridge vlan del dev v1b vid 1
```

`bridge vlan show` 里标了 `PVID` 的那一行就是不带 tag 的帧进的 VLAN。旁边若还有 `Egress Untagged`，这个 VLAN 的帧从这个口出去时会去掉 tag。

Trunk 可以同时带多个 VLAN。其中一行仍然可以是 PVID，不带 tag 的帧进这一行。这一行也叫 native VLAN。其余 VLAN 在线上带着 tag。还没有网桥时，用下面这一套看表。`bridge vlan del` 若提示 VLAN 1 不存在，跳过那一行。

```bash
ip link add br0 type bridge vlan_filtering 1
ip link set br0 up
ip link add v3 type veth peer name v3b
ip link set v3b master br0 up
bridge vlan add dev v3b vid 10 pvid untagged
bridge vlan add dev v3b vid 20
bridge vlan del dev v3b vid 1
bridge vlan show dev v3b
```

`bridge vlan show` 里 `v3b` 应有两行：10 带 `PVID` 和 `Egress Untagged`，20 没有这两样。20 进出都带 tag。

两端 Trunk 的 PVID 必须相同。一侧 PVID 是 10，发出去的 VLAN 10 帧不带 tag。另一侧 PVID 是 20，会把这帧放进 VLAN 20。两边都觉得自己在转发，帧已经进了另一个 VLAN。ping 若因此通了，不能当成 VLAN 配对正确，要先对一下两边的 `bridge vlan show`。
